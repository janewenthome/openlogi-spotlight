# ADR-001: Use a companion AppKit overlay

## Status

Accepted

## Context

OpenLogi already owns Logitech HID++ communication and button remapping, but its current action catalog does not include a presentation spotlight. Modifying its Rust agent would couple a presentation feature to a large, actively changing HID application and would require maintaining a fork.

## Decision

Keep OpenLogi as an external prerequisite. Map a physical button to a dedicated modifier-free function key (`F13` by default), then let a small native AppKit app listen for that key and render a click-through overlay.

## Consequences

### Positive

- Small, independently testable codebase.
- No copied OpenLogi code or brand assets.
- Works with any input device that can emit the configured shortcut.
- The overlay can be iterated without touching HID or event-hook code.

### Negative

- Users must configure one OpenLogi binding in addition to installing this app.
- macOS Accessibility permission is required for the global shortcut monitor.
- The first release is macOS-only.

### Future extension

A future OpenLogi plugin or upstream action could replace the keyboard-shortcut bridge, but it is intentionally outside the MVP.
